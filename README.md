# Итоговое тестирование — статический сайт для GitHub Pages

Два независимых теста («Брови» и «Ресницы») на одном статическом сайте.
Ученица открывает персональную ссылку и видит только свой тест — меню выбора нет.
Результат автоматически уходит вам в Telegram через отдельный serverless-прокси.

---

## Структура проекта

```
/
├── index.html              ← единственная страница приложения
├── 404.html                ← аккуратная страница ошибки
├── .nojekyll               ← чтобы GitHub Pages не обрабатывал файлы Jekyll
├── brows/index.html        ← короткая ссылка → ?test=brows
├── lashes/index.html       ← короткая ссылка → ?test=lashes
├── assets/
│   ├── css/styles.css      ← вся визуальная система
│   └── js/
│       ├── config.js       ← ВСЕ настройки (проходной балл, Telegram, перемешивание)
│       ├── data/
│       │   ├── brows.js    ← вопросы теста «Брови»
│       │   └── lashes.js   ← вопросы теста «Ресницы»
│       ├── engine.js       ← логика: типы вопросов, подсчёт, ключи ответов
│       └── app.js          ← интерфейс
└── worker/
    ├── worker.js           ← Cloudflare Worker для Telegram
    └── wrangler.toml
```

## Как запустить локально

Открывать `index.html` двойным кликом **не нужно** — из-за `file://` часть
браузеров блокирует загрузку скриптов. Запустите простой сервер:

```bash
# Python 3
python3 -m http.server 8000

# или Node
npx serve .
```

Затем откройте:

* http://localhost:8000/?test=brows
* http://localhost:8000/?test=lashes

В VS Code удобно использовать расширение **Live Server** (правый клик по
`index.html` → «Open with Live Server»).

## Ссылки для учениц

После публикации на GitHub Pages:

**Брови**

```
https://USERNAME.github.io/REPOSITORY/?test=brows
```

**Ресницы**

```
https://USERNAME.github.io/REPOSITORY/?test=lashes
```

Работают также короткие варианты (это просто редиректы):

```
https://USERNAME.github.io/REPOSITORY/brows/
https://USERNAME.github.io/REPOSITORY/lashes/
```

> **Почему именно `?test=`.** GitHub Pages — статический хостинг без
> серверной маршрутизации. Путь вида `/test/brows/` работает, только если
> в репозитории физически есть такая папка с `index.html`. Query-параметр
> надёжен всегда: одна страница, один файл, никаких 404 при прямом
> открытии и при обновлении страницы. Папки `brows/` и `lashes/` добавлены
> для красивых ссылок и просто перенаправляют на `?test=…`.

Ученица не видит второго теста: на сайте нет ни списка тестов, ни
переключателя. Открытая без параметра главная страница показывает
нейтральное «Добро пожаловать», а неизвестный `?test=` — «Тестирование не найдено».

## Как залить сайт на GitHub и включить GitHub Pages

1. Создайте репозиторий на github.com (например `test`).
2. Загрузите содержимое папки проекта в корень репозитория
   (кнопка **Add file → Upload files**, перетащите все файлы и папки).
   Либо через терминал:

   ```bash
   git init
   git add .
   git commit -m "Итоговое тестирование"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

   Папку `worker/` можно залить вместе с остальным — она не мешает сайту.
3. В репозитории откройте **Settings → Pages**.
4. В блоке **Build and deployment**: Source = **Deploy from a branch**,
   Branch = `main`, папка `/ (root)`. Нажмите **Save**.
5. Через 1–2 минуты сайт будет доступен по адресу
   `https://USERNAME.github.io/REPOSITORY/`.

## Как добавить вопросы

Вопросы лежат в `assets/js/data/brows.js` и `assets/js/data/lashes.js`.
Количество вопросов нигде не прописано — оно считается автоматически.

### Один правильный ответ

```js
{
  id: 51,
  block: 'Название блока',           // необязательно
  type: 'single',
  question: 'Текст вопроса?',
  options: [
    { id: 'a', text: 'Вариант 1' },
    { id: 'b', text: 'Вариант 2' }
  ],
  correct: ['b'],
  explanation: 'Почему именно так.'  // необязательно
}
```

### Несколько правильных ответов

```js
{
  id: 52,
  type: 'multiple',
  question: 'Выберите все подходящие варианты.',
  options: [ /* … */ ],
  correct: ['a', 'c', 'd']
}
```

Полный балл начисляется только если выбраны **все** правильные и **ни одного** лишнего.

### Сопоставление

```js
{
  id: 53,
  type: 'matching',
  question: 'Соотнесите элементы.',
  left:  [ { id: 'l1', text: 'Головка' }, { id: 'l2', text: 'Хвост' } ],
  right: [ { id: 'a',  text: 'Начало' },  { id: 'b',  text: 'Конец' } ],
  correct: { l1: 'a', l2: 'b' }
}
```

### Последовательность

```js
{
  id: 54,
  type: 'order',
  question: 'Расставьте этапы по порядку.',
  items: [
    { id: 'a', text: 'Второй шаг' },
    { id: 'b', text: 'Первый шаг' }
  ],
  correct: ['b', 'a']     // правильный порядок по id
}
```

Стартовый порядок на экране всегда перемешивается, чтобы ответ не был виден сразу.

### Открытый ответ

```js
// с автоматической проверкой
{
  id: 55,
  type: 'text',
  question: 'С каким слоем кожи работает бровист?',
  hint: 'Одно слово',
  acceptedAnswers: ['эпидермис', 'эпидермисом'],
  explanation: '…'
}

// без автоматической проверки — уходит на ручную проверку
{
  id: 56,
  type: 'text',
  question: 'Ответьте своими словами…',
  manualReview: true,
  reference: 'Эталонный ответ, который увидит ученица только в разборе.'
}
```

### Ситуационная задача

```js
{
  id: 57,
  type: 'situation',
  situation: 'Описание ситуации — выводится в отдельном блоке.',
  question: 'Что вы будете делать?',
  // либо варианты ответа:
  options: [ /* … */ ],
  correct: ['c']
  // либо открытый ответ: manualReview: true + reference
}
```

**Важно:** `id` внутри одного теста должны быть уникальными. Нумерация
на экране («Вопрос 12 из 50») считается от порядка в массиве, а не от `id`,
поэтому удалять и добавлять вопросы можно свободно — навигация не сломается.
Правильность ответа всегда определяется по `id` варианта, а не по его позиции,
поэтому перемешивание ничего не ломает.

## Как создать новый тест

1. Скопируйте `assets/js/data/brows.js` в `assets/js/data/NEWTEST.js`.
2. Поменяйте внутри:

   ```js
   window.__TESTS__.newtest = {
     id: 'newtest',
     title: 'Название теста',
     description: '…',
     questions: [ /* … */ ]
   };
   ```
3. Подключите файл в `index.html` рядом с остальными:

   ```html
   <script src="assets/js/data/NEWTEST.js"></script>
   ```
4. Ссылка: `https://USERNAME.github.io/REPOSITORY/?test=newtest`.
5. При желании скопируйте папку `brows/` в `newtest/` и поправьте в ней адрес редиректа.

## Перемешивание

`assets/js/config.js`:

```js
SHUFFLE_QUESTIONS: false,   // перемешивать порядок вопросов
SHUFFLE_OPTIONS:  false,    // перемешивать варианты ответа
```

По умолчанию выключено, потому что вопросы идут тематическими блоками.
Включение ничего не ломает: у `order` перемешивается только стартовая
раскладка, у `matching` — только правая колонка, а правильность везде
проверяется по `id`.

## Правила подсчёта

| Тип | Правило |
|---|---|
| `single` | верно → 1 балл, иначе 0 |
| `multiple` | 1 балл только если выбраны все верные и ни одного лишнего |
| `matching` | частичный балл за каждую верную пару (`PARTIAL_MATCHING: true`) |
| `order` | 1 балл только за полностью верную последовательность (`PARTIAL_ORDER: false` — можно включить частичный) |
| `text` | автопроверка только при наличии `acceptedAnswers`, иначе «требует проверки» |
| `situation` | с вариантами — как `single`; без вариантов — как открытый ответ |

Вопросы с `manualReview: true` по умолчанию **не входят** в итоговый процент
(`MANUAL_REVIEW_SCORING: 'exclude'`) и показываются отдельным счётчиком
«на проверке». Можно переключить на `'correct'` или `'incorrect'`.

Вся логика подсчёта собрана в двух функциях `evaluate()` и `scoreAttempt()`
в `assets/js/engine.js` — правила меняются в одном месте.

## Сохранение прогресса

Прогресс пишется в `localStorage` под ключами `test_brows_progress`
и `test_lashes_progress` — отдельно для каждого теста. Сохраняются имя,
выбранный тест, текущий вопрос, все ответы, время начала и ID попытки.

При повторном открытии ссылки ученица увидит предложение «Продолжить
тестирование» / «Начать заново». Если тест уже завершён — сразу откроется
экран результата, и повторное уведомление в Telegram **не отправится**.

Если `localStorage` недоступен (режим инкогнито с жёсткими настройками),
сайт продолжает работать — прогресс просто хранится в памяти вкладки.

## Как подключить Telegram

Сайт статический, поэтому токен бота **нельзя** класть в JavaScript — его
увидит любой, кто откроет исходный код страницы. Схема такая:

```
Браузер ученицы  →  Cloudflare Worker (токен здесь)  →  Telegram Bot API
```

Сайт отправляет на Worker только результат:

```json
{
  "attemptId": "BROWS-20260919-184201-AB12CD",
  "test": "brows",
  "testName": "Брови",
  "studentName": "Анна Иванова",
  "score": 84,
  "correct": 42,
  "total": 50,
  "errors": 8,
  "manual": 4,
  "passed": true,
  "duration": 1114,
  "openAnswers": [ { "n": 4, "question": "…", "answer": "…" } ]
}
```

### 1. Как создать Telegram-бота

1. Напишите в Telegram боту **@BotFather**.
2. Команда `/newbot` → придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `1234567890:AAH...`. **Это секрет.**

### 2. Где взять CHAT_ID

Простой способ:

1. Напишите своему новому боту любое сообщение (например «привет»).
2. Откройте в браузере:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
3. Найдите в ответе `"chat":{"id":123456789,...}` — это ваш `CHAT_ID`.

Если хотите получать уведомления в группу: добавьте бота в группу,
напишите там сообщение и снова откройте `getUpdates` — у групп `id`
отрицательный, например `-1001234567890`.

Альтернатива: напишите боту **@userinfobot** — он пришлёт ваш ID.

### 3. Как задеплоить Cloudflare Worker

**Вариант А — через сайт Cloudflare (без терминала):**

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com) (бесплатного плана хватает).
2. **Compute (Workers) → Create → Start from Hello World → Deploy**.
3. Нажмите **Edit code**, удалите весь код и вставьте содержимое `worker/worker.js`. **Deploy**.
4. Откройте **Settings → Variables and Secrets** и добавьте:

   | Имя | Тип | Значение |
   |---|---|---|
   | `BOT_TOKEN` | Secret | токен от BotFather |
   | `CHAT_ID` | Secret | ваш chat_id |
   | `ALLOWED_ORIGINS` | Text | `https://USERNAME.github.io` |
   | `CLIENT_KEY` | Secret | (необязательно) любая строка |

5. Сохраните и задеплойте ещё раз.
6. Скопируйте адрес Worker'а, например
   `https://test-telegram-proxy.ВАШ-АККАУНТ.workers.dev`.

**Вариант Б — через терминал:**

```bash
cd worker
npx wrangler login
npx wrangler secret put BOT_TOKEN
npx wrangler secret put CHAT_ID
npx wrangler secret put CLIENT_KEY      # необязательно
npx wrangler deploy
```

Не забудьте поправить `ALLOWED_ORIGINS` в `wrangler.toml`.

### 4. Подключить Worker к сайту

В `assets/js/config.js`:

```js
TELEGRAM_ENDPOINT: 'https://test-telegram-proxy.ВАШ-АККАУНТ.workers.dev',
TELEGRAM_CLIENT_KEY: '',   // та же строка, что в CLIENT_KEY, если задавали
```

Готово. Пока поле `TELEGRAM_ENDPOINT` пустое, тест работает полностью —
просто без уведомлений.

### Что придёт в Telegram

```
🎓 НОВОЕ ТЕСТИРОВАНИЕ

📚 Тема: Брови
👩‍🎓 Ученица: Анна Иванова

📊 Результат: 84%
✅ Правильных: 42/46
❌ Ошибок: 4
📝 Открытых ответов на проверку: 4

🏆 Статус: ✅ ПРОЙДЕНО (порог 80%)
⏱ Время прохождения: 18 мин 34 сек

📅 Дата: 19.09.2026
🕐 Время: 18:42

🆔 BROWS-20260919-184201-AB12CD
```

Вторым сообщением приходят тексты открытых ответов (если
`SEND_OPEN_ANSWERS_TO_TELEGRAM: true`). Длинные ответы автоматически
разбиваются на несколько сообщений.

Сообщение формируется в HTML-режиме Telegram, все пользовательские
значения экранируются (`&`, `<`, `>`), поэтому текст ученицы не может
сломать разметку.

### Защита от повторной отправки

Каждая попытка получает уникальный `attemptId`
(`BROWS-20260919-184201-AB12CD`), который хранится в `localStorage`
вместе с флагом «отправлено». Обновление страницы после результата
повторное уведомление **не** вызывает. Если отправка не удалась,
ученица увидит сообщение «Результат сохранён. Не удалось отправить
уведомление» и кнопку «Повторить отправку»; при следующем открытии
страницы сайт попробует отправить ещё раз сам.

## Работа без интернета

Все вопросы и вся логика загружаются вместе со страницей. Интернет нужен
только в момент отправки результата в Telegram (и один раз — чтобы
подгрузить шрифты Google Fonts; без них сайт просто использует системный
шрифт). Если соединения нет, тест проходится полностью, результат
сохраняется, а уведомление можно отправить позже кнопкой.

## Возможные проблемы и ограничения

1. **Правильные ответы принципиально нельзя спрятать полностью.**
   Сайт статический: файл `assets/js/data/brows.js` доступен любому, кто
   откроет исходный код. В интерфейсе ключ не показывается, в DOM и в
   консоль не попадает, из `window` после загрузки удаляется — но это
   защита от случайного подглядывания, а не настоящая защита. Если она
   критична, нужен сервер, который отдаёт вопросы без ответов и считает
   результат на своей стороне.

2. **Результат можно подделать.** Любой клиентский тест можно пройти
   «в обход» через инструменты разработчика. Telegram-уведомление стоит
   воспринимать как удобную сводку, а не как защищённый протокол.

3. **`localStorage` привязан к браузеру и устройству.** Начатый на
   телефоне тест не продолжится на компьютере. В режиме инкогнито
   прогресс исчезнет при закрытии вкладки.

4. **Предупреждение при закрытии вкладки** показывается не всегда: часть
   мобильных браузеров игнорирует `beforeunload`. Прогресс всё равно
   сохраняется автоматически после каждого действия.

5. **Cloudflare Worker бесплатного плана** — 100 000 запросов в сутки,
   этого хватает с огромным запасом. `CLIENT_KEY` виден в коде страницы,
   поэтому он отсекает только случайные запросы, а не целенаправленный
   спам. При необходимости добавьте на Worker Cloudflare Rate Limiting
   или проверку по `Referer`.

6. **Google Fonts** требуют интернета при первой загрузке. Если хотите
   полную автономность — скачайте шрифты в `assets/fonts/` и подключите
   через `@font-face`, убрав `<link>` из `index.html`.

7. **Открытые ответы** проверяются автоматически только при наличии
   `acceptedAnswers` и сравниваются по вхождению нормализованной строки
   (без регистра, «ё» = «е»). Развёрнутые ответы помечены
   `manualReview: true` и проверяются вами вручную.

## Итоговая проверка сценариев

Проект проверен по сценариям: открытие обоих тестов, ввод имени,
прохождение вопросов всех шести типов, навигация вперёд/назад,
обновление страницы и восстановление прогресса, завершение теста,
экран результата, разбор ошибок, защита от повторной отправки,
ошибка отправки и повторная попытка, неизвестный `?test=`, мобильные
ширины 360/390/430/768/1024/1440.
